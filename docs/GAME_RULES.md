# Game Design Rules

## Central rule

**副本真相固定，但故事不存在固定劇本。**

## Loop

現實／中間安全空間 → 副本通知 → 準備 → 進入副本 → 學習環境 → 任務與危險 → 探索／推理／戰鬥／交易／合作 → 局勢惡化或改變 → 關鍵決策 → 完成／部分完成／失敗／撤退 → 結算 → 安全空間。

## World

- locals do not know they are NPCs
- locals have lives, interests, fears, relationships, resources, secrets
- information is earned through observation, people, documents, environment, combat, testing, items and reasoning
- correct reasoning must be respected
- no retroactive rewrite of a fixed truth

## NPC

Conflict should arise from:
- goals
- fears
- information
- interests
- bottom lines

Betrayal must have a cause.

Persistent teammates remember:
- promises
- debts
- deaths
- resources
- relationship changes
- previous choices

## Combat

Combat is driven by:
- information
- rules
- terrain
- preparation
- cooperation
- judgment

Avoid repetitive attack turns. One action may resolve an entire tactical segment.

## Player actions

Every turn supports:
- four new concrete choices
- free text input
- up to three authorized TAGs

The four choices are suggestions, not guaranteed successes.

## Narrative

Preferred structure:

```
action
→ environment response
→ NPC action/dialogue
→ observable information
→ consequence
→ next pressure
```

Use variable length based on dramatic weight rather than a fixed minimum.
